# Ежедневный workflow

## Утро / старт БАЗИС

1. Открыть БАЗИС-Мебельщик, вкладку «Мебельщик», модель.
2. Меню **«Скрипты» → `0_BasisMCP_worker`** (первый пункт, без диалогов).
   В статус-строке появится `🟢 AI Active`. Всё — worker работает весь день.
3. В OpenCode проверить связь: агент вызывает `basis_status` →
   `worker-listening`, heartbeat свежий.

## Работа

1. Пользователь ставит задачу обычным языком: «покажи дерево», «создай панель
   800×600», «замени материал у всех панелей на ЛДСП Белый», «поставь кромку».
2. Агент кладёт команды в очередь (`basis_execute`), таймер исполняет их за ~2 с.
3. Агент проверяет результат чтением (`basis_model_summary`, `object_info`) и
   отчитывается «было → стало».

## Если связи нет

| Симптом | Причина | Действие |
|---|---|---|
| `worker-idle-waiting` | сессия умерла (ESC / другой скрипт) | «Скрипты» → `0_BasisMCP_worker` |
| `not-running` | БАЗИС перезапущен | то же |
| `timeout` при `basis_execute` | worker мёртв или модальный диалог в БАЗИС | закрыть диалог / перезапустить worker |
| операция «unknown op» | старая версия worker'а | перезапустить worker (новый код) |

Накопленная очередь **не теряется**: при старте worker'а backlog исполняется сразу.

## Завершение дня

- Модель сохраняется пользователем вручную («Файл → Сохранить»), скрипты модель
  не сохраняют.
- Worker можно не останавливать — умрёт вместе с БАЗИС.

## Разработка (для агента)

1. Правки: `bridge/basis_mcp_worker.js` (операции), `server/src/index.js` (MCP).
2. Проверка worker'а: `node --check`, ASCII-контроль (0 байт >127).
3. Деплой: `tools/install-worker.ps1` (или копирование вручную под именами 0_/1_).
4. Перезапуск worker'а пользователем → `basis_status` → тестовый `ping`.
5. Журнал: `research/NOTES.md`; операции — `docs/OPERATIONS.md`.
