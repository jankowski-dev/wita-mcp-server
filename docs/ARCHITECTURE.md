# Архитектура

## Схема

```
┌──────────┐  MCP (stdio)  ┌───────────────────┐   файлы    ┌──────────────────────┐
│ OpenCode │◄─────────────►│ server/src/index  │◄──────────►│  C:\Users\Public\    │
│  (ИИ)    │               │ (Node.js, SDK)    │            │  basis-mcp\inbox     │
└──────────┘               └───────────────────┘            │           outbox     │
                                                            │           states     │
                                                            │           log        │
                                                            └──────▲───────────────┘
                                                                   │ fs.readdir/read/write
                                                   ┌───────────────┴───────────────┐
                                                   │  БАЗИС-Мебельщик 2022         │
                                                   │  0_BasisMCP_worker.js         │
                                                   │  (резидентная input-сессия)   │
                                                   └───────────────────────────────┘
```

## Протокол обмена

- Команда: `inbox/cmd_<id>.json` — `{id, op, params, sentAt}`; запись атомарная (tmp → rename).
- Результат: `outbox/res_<id>.json` — `{id, status: ok|error, result|error, durationMs, worker}`.
- Heartbeat: `states/heartbeat.json` — `{ts, workerVersion, mode, processedTotal}`;
  обновляется таймером каждые 2 с, пока сессия жива.
- Журнал: `log/worker.log`; обработанные команды архивируются в `log/processed/`.
- Сервер поллит `outbox` каждые ~100 мс до таймаута операции (по умолчанию 15–30 с).

## Жизненный цикл worker'а

1. Пользователь: меню «Скрипты» → `0_BasisMCP_worker`.
2. Bootstrap: создать каталоги → **initial pump** (исполнить накопленную очередь) →
   создать кнопку `🟢 AI Active` (хоткей Shift+1) → записать `states/worker-online.json`.
3. `Action.Continue()` — включает режим прерываний; **возвращается сразу**.
4. `setInterval(2000)` — автозапуск очереди; heartbeat пишется на каждом тике.
5. `$input(id)` — ручной запуск по кнопке/Shift+1 (резервный канал).
6. Конец сессии: ESC / запуск другого скрипта / перезапуск БАЗИС. Все незавершённые
   команды остаются в `inbox` и будут исполнены при следующем старте worker'а.

## Почему так, а не иначе

- **Прямого API у внешнего процесса нет.** Единственный мост — скрипт, исполняемый
  внутри БАЗИС.
- **Таймер работает только в «живой» сессии.** Скрипт, завершившийся после
  `setInterval`, теряет интервалы (проверено: ~3 мин и смерть). Сессия, удерживаемая
  `Action.Continue()`, держит таймер живым часами (проверено 6+ минут в мониторинге,
  фактически — весь рабочий день).
- **Commit-модель**: изменения скрипта не видны модели, пока не вызван
  `Action.Commit()`; поэтому каждая мутирующая операция коммитит результат.

## Версионирование worker'а

Версия в `BASIS_MCP_VERSION` (bridge) и в каждом результате (`worker.version`).
Сервер показывает её в `basis_status`. Правило: правки worker'а → bump версии →
перезапуск пользователем (старая сессия продолжает работать на старом коде).
