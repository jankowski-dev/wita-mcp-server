## Документированные факты

### Запуск скриптов
- Скрипты — `.js` (движок понимает и TS: классы, аннотации) в `C:\Users\<user>\Documents\BazisX\Scripts\` (X = версия).
- Появляются в разделе «Скрипты» главного меню; запуск — клик по имени; Ctrl+клик — открыть в редакторе.
- Отладка через VS Code + плагин `bazissoft.bazis-debug2` (Debugger for Bazis scripts).
- В редакторе есть шифрование кода с привязкой к ключу защиты (secureExec).

### Новый API (v5, встроенные модули)
- `objects3d` — создание панелей (PanelOrientation front/vertical/horizont), контуров, профилей, тел по траектории, структурных объектов (блок, полуфабрикат, покупное изделие).
- `modelIOOperations` — SaveModelToFile / LoadModelFromFile (.b3d), экспорт в сторонние полигональные форматы. ВАЖНО: после Load старые ссылки на объекты уничтожаются.
- `currentFileData` — активный файл модели (model, filename).
- `interaction` — события окна модели (SetMouseMoveHandler, SetMouseDownHandler, SetKeyDownHandler), запрос объектов/точек у пользователя (getRequest.GetVector/GetObject).
- `UI.dialogs` — MessageBox, RunMessageDialog, RunOpenFileDialog/RunSaveFileDialog, RunYesNoDialog.
- `apiVersion` — Get/SetScriptApiVersion (совместимость старых API через шимы).
- `execution.ContinueExecution()` — скрипт продолжает жить и обрабатывать события, пока пользователь его не отменит (Escape).
- История/undo: встроенные функции сами регистрируют изменения; при прямом изменении свойств надо регистрировать изменение вручную до правки; можно сохранять промежуточные изменения в отдельную операцию истории, отменять изменения скрипта.

### Старый API (v0, часть функционала живёт в новых версиях через шимы)
- Глобальные: `system`, `Model`, `Action`, `ActiveMaterial`; методы AddPanel/AddFrontPanel/AddHorizPanel/AddVertPanel/AddExtrusion/AddTrajectory/AddBlock/AddAssembly, StartEditing, BeginBlock/EndBlock, DeleteObject, NewButtonInput/NewFloatInput/NewNumberInput/NewMaterialInput/NewButtMaterialInput...
- `NewCOMObject(CLSID)` — COM-автоматизация: `Word = NewCOMObject('Word.Application')`.
- `NewForm()` — экранная формы (визуальный режим генерации кода формы).
- `system.exec('c:/Windows/system32/calc.exe')` — запуск внешней программы.
- `readTextFile/writeTextFile/fileExists/getFileName/askFolder/askFileNameSave` — файловый IO.
- `console.log` есть в v5; в старом — `alert/confirm/prompt`.

### Критичные находки для моста MCP ↔ БАЗИС
- `require('fs')` и `require('path')` работают внутри движка (пример с readFileSync/writeFileSync в официальных примерах).
- COM (`NewCOMObject`) доступен (обект Word работает) — потенциально XMLHTTP для HTTP.
- `system.exec` — запуск внешних программ (старый API).
- НИКАКИХ документированных таймеров (setInterval/setTimeout) и сетевых функций не найдено.
- События окна модели (мышь/клавиатура) — единственный документированный «тик» для резидентного скрипта.
- Т.lua/.js прямо в каталоге Scripts — катал BazisSoft использует node_modules и TS.

  основного тела скрипта (так читается пример стр. 2810: `$move` определён ПОСЛЕ
  `Continue` и работает благодаря hoisting'у).
- Клик по кнопке в прерывательном режиме подтвердился: `input event id=1
  btnId=1 ours=true` → pump → `ping -> ok (0 ms)`.
- `Action.Commit()` работает: панель создана и сразу видна в дереве
  (Count=3: рамка + TestPanel 100x200 + TestPanel2 150x150, толщины/контуры
  читаются). Изменения применились В ТОЙ ЖЕ сессии.
- Нюанс: чтение `panel.Name` сразу после Commit даёт "" (объект перерождается

- ОТКРЫТИЕ семантики свойств (критично): присвоения ДО первого `Commit`

## Первый успешный WRITE и правило Commit (2026-11-08, v0.3.1/0.3.2)

## Инцидент 2: $input не вызывался без Action.Continue() (2026-11-08 22:4x)

  `function $input(id)` — каноническая схема мастераInput-стадии.
- FIX v0.3.1: `Action.Continue()` в хвосте (в try/catch, с логом входа/выхода);
  `$input` логирует КАЖДОЕ событие (id, btnId, ours) — больше не пропустим «тихий»

## Архитектурные варианты моста (история рассуждений)
1. Файловый ящик (inbox/outbox JSON): MCP пишет команды, мост читает/исполняет/пишет результат. Требует решения «живучести».
2. Резидентный мост через долгий HTTP-поллинг (XMLHTTP через COM или require('http') — проверить).
3. Мост через `exec` + внешний коннектор (естественный Tailwind: bridge периодически тикает).
4. «Мышинный тик» через SetMouseMoveHandler (хак, документированный API).
