# Уроки движка БАЗИС (выстрадано)

Проверено на **БАЗИС-Мебельщик 2022.12.21 (сборка 36090)**. Документация движка —
«Работа со скриптами» (старое API).

## Среда

- Скрипты: `C:\Users\<user>\Documents\Bazis\Scripts\*.js` (имя папки зависит от версии).
- Движок читает исходник как **CP1251** → все файлы **строго ASCII**; русские
  строки собирай `\uXXXX`-экранированием в рантайме.
- `require()` даёт Node-набор: `fs, path, os, net, http, https, child_process,
  util, crypto, events, timers, url, process`. Работает COM (`NewCOMObject`).
- Нового API (v1–v5: `currentFileData`, `objects3d`, `interaction`, …) в 2022 **нет**.

## Живучесть скрипта

- Скрипт, завершившийся после `setInterval`, **теряет таймеры** (~3 минуты и смерть —
  проверено на таймерном мосте v0.2.0).
- `Action.Continue()` **не блокирует**: включает обработку прерываний после тела
  скрипта; сессия живёт, `setInterval`/`$input` продолжают работать (проверено).
- `$move` (движение мыши) в обычном режиме НЕ вызывается — только в активных
  action-режимах (например, `BeginOrtho3`). Как триггер не годится.
- Сессию убивают: ESC, запуск другого скрипта, перезапуск БАЗИС, интерактивный
  выбор в `NewButtMaterialInput` (после выбора материала кнопки исчезают).
- `NewButtonInput(hint)` создаёт кнопку в статус-строке; хоткей — авто (Shift+1,
  Shift+2… по порядку кнопок в сессии). Emoji-иконка рендерится монохромно —
  цвет текста не задаётся.

## Модель

- `AddFrontPanel(x1,y1,x2,y2,z)`, `AddHorizPanel(x1,z1,x2,z2,y)`,
  `AddVertPanel(z1,y1,z2,y2,x)` — порядок аргументов разный, см. OPERATIONS.md.
- Изменения скрипта = «новые объекты скрипта»: в дерево попадают только после
  `Action.Commit()` (или завершения скрипта). Свойства, заданные **до** коммита,
  переносятся в модель; присвоения **после** коммита уходят в мёртвую обёртку.
- Чтение дерева: `Model.Count`, `Model.Objects[i]`; у панели:
  `ContourWidth/ContourHeight/Thickness/Butts.Count/MaterialName`; у объекта:
  `Position`, `GMax`, `GMin` (Vector).
- Кромка: `panel.AddButt(material, elem)`, elem 0..3 (против часовой стрелки от
  начала координат). Материал — объект `NewButtMaterialInput` (интерактивный).
  Строка с именем материала **молча игнорируется**.
  ⚠ Пикер берёт ПЕРВУЮ кромку базы как дефолт — этого достаточно для скриптов.
- Фурнитура: `OpenFurniture(path)` → `Mount(panel1,panel2,x,y,z)`,
  `Mount1(panel,x,y,z,angle)`, `MountScheme(panel1,panel2,FurnPos,BasisPoint)`
  (крепеж на стык!), `MountBox(Position,Size,axisZ,axisY)`, `Make(t1,t2)`.
  Кириллические пути `.f3d` проходят через JSON без искажений.
- `ModelFilename` пуст, пока модель не сохранена файлом.

## Крепёж: семантика координат (эмпирика)

- `Mount(panel1, panel2, x,y,z)` — точка в зоне стыка, координаты **глобальные, мм**.
- Ось крепежа = нормаль плоскости стыка: боковина↔дно — вертикально; боковина↔полка —
  горизонтально (снаружи боковины в торец полки).
- **Порядок панелей влияет на центровку**: `Mount(полка, боковина)` центрует по
  толщине полки; обратный — сажает на верхнюю кромку (проверено `object_info`:
  y=2008 vs y=2016 при полке 2000..2016).
- Петли: `Mount(боковина, дверь, 32, высота, 0)` — образец из «Редактируемая тумба.js»;
  садится на внутреннюю плоскость боковины, чашка — в дверь.

## Производительность (проверено)

- `add_panel`, `add_butt`, `mount` конфирмата — 0–3 мс.
- `mount` сложной фурнитуры (евровинт-файл) до 3.5 с при первом открытии файла.
- Батч 100+ команд за один тик — нормально (весь шкаф собран за ~1–2 с на батч).

## UX-решения

- Файлы в папке скриптов названы `0_BasisMCP_worker.js` / `1_BasisMCP_stop.js` —
  префикс держит их первыми в меню.
- Стартовый alert убран (меньше кликов); индикатор — кнопка `🟢 AI Active`.
- Синтетический ввод (SendKeys/клики/PostMessage/UIA) движок **игнорирует** —
  автоматизировать меню извне нельзя; запуск worker'а остаётся ручным (1 клик).
