## 3. Рекомендации по улучшению работы модели в программе (⛵приоритет для материалов)

### 3.1. Декларативные операции (что даст модели «продвинутую работу»)
**P1 — разблокирующие (без них не успевать за):**
- `set_pocket`/`cut_rect` — прямоугольные вырезы в панель с заданными сторонами/глубиной (фаска/опоры/скруглители — стандарт детали).
- `set_window`/`add_hole` — отверстия под крепеж (Ø3/5, ⌀-штуф) с данными по System 32.
- `chamfer`/`round_edge` — фаски/рез кромки (кромка контура сверху ящика: 0.5-1.0 мм — стандарт WITA) — себестоимость ниже.
- `place_section`/`frame_section` — круглые верхера (короткие).
- `draw_profile`/`polyline_cut` — общий для полок/открытых (нужно координатное описание).
- `attach_shank`/`attach_gasket` — шпаклефитраль (себестоимость).

**P2 — постепенные (высокая ценность):**
- `trim_panel` — пересечение панели с плоскостью/ребром; `place_part` — компонент-не-алгоритм (фурнитура разная по весам).
- `top_plate` — установка столешницы поверх верхних корпусов (риск: задеть другие выступы).
- `fasteners_pack` — пакетный порядок присадки по System32 (числа из 8.1.5/8.3.5 руководства).
- `check_panel_intersections` — есть функция-проверка пересечений в стандарте БАЗИС (`checkIntersects`), нужен wrapper в worker + батарея.

### 3.2. Рабочий процесс (производство/документация)
- `generate_stp`/`stp_spec_pack` (Ф4): автоспецификация по отступам и кромкам — разобраны все стандарты пошагово (в ходе задачи).
- `validate_design` — battery-файл чек-листа (WITA + GTV цифры; контроль зазоров, System32, формат конфирматов — шаблон после батарей).
- `dimensioning_plan` — расчёт высот (WITA-формулы; правила дизайна кухни).

### 3.3. Автоматизация коммуникации и продукта (Ф2-Ф4)
- `present_snapshot` — автогенерация 2D-схемного показа (из дерева); подтвердительная панель перед стартами (есть заготовка в экосистеме).
- `save_build_snapshot`/`build_log_export` — отчётность коммитов (шаблон в NOTES).
- `kitchen_auto` — пакет работ по кухне (стандартизировано: 2-4 батареи/сессия максимум).
- `label_solution` — бирка с материалами/артикулами (для мелкой серии).

### 3.4. Процессное (Ф4, 3 месяца)
- Verification system: battery tests на базе движка каждую N недель, по правилу E2E ( батарея = создание+мутация+верификация+откат+README отчёт).
- `agent-auth` таблица — установить типы автоподтверждений + процедуру включения/выключения полных авторных прав.

### 3.5. Продуктовое (см программа-паузу)
